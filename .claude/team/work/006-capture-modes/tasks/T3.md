# T3 Frontend plumbing: IPC, store, liveness, fixtures
Depends on: T1 (bindings). Parallel: yes with T2 (command name `set_capture_mode`, arg `{ mode }`,
returns null; mock it). Worktree: recommended if run with T2.

Files: `src/ipc/commands.ts`, `src/state/session.ts` (+ `session.test.ts`), `src/state/liveness.ts`
(+ `liveness.test.ts`), `src/test/fixtures.ts` (`captureMode: 'continuous'`), any mock of `api`.

Acceptance
- `setCaptureMode(mode)` store action: busy op `'settingMode'`, error surfaces as `commandError`,
  state only changes when the backend status arrives.
- `liveness(state, frame, now, mode)` gets a `capturing` kind: single + acquiring -> label
  `CAPTURING`, never `LIVE`, never stale; continuous and non-acquiring results unchanged;
  `useLiveness` passes the mode through. Callers updated.

Tests: liveness matrix (single/continuous x acquiring/with-frame/without-frame/stale/disconnected),
store action success and failure. `npm run check` green.
