# T2 Core: a plug-in during an in-flight (failing) connect is not dropped

Parallel with T1 (disjoint files). Plan: `../plan.md` (secondary finding).

## Goal
`Reconnect` pressed while the device is absent runs the driver's retry ladder in state `Connecting`.
A plug-in event arriving in that window must still connect the device once that attempt has failed.

## Files
- `crates/spectrum-core/src/autoconnect.rs` (`Policy::on_event`, Added branch; doc comment)
- `crates/spectrum-core/tests/autoconnect.rs` (new tests)
- `docs/adr/0014-auto-connect-and-device-watch.md` only if it states the `Disconnected` precheck (one line)

## Change
In the `Added` branch replace `if !self.is_idle() { return; }` with a check that returns only when
a source is `Connected` or `Acquiring`. `Connecting` and `Disconnecting` continue to
`discover` + `remember::auto_connect`, whose `connect_if_idle` waits on the worker lock and then
re-checks, so a successful manual connect is never replaced. Leave `launch` as is. No new locks, no
driver or UI change; no bindings change.

## Acceptance
- R1: connected -> `Removed` (or fatal read) -> manual `connect` fails (`failing_opens`) -> `Added`:
  ends `Connected`, `lastNotice == None`, `connectFailed` not shown; one extra successful open.
- R2: manual connect parked in `open` (gate), state `Connecting`; `Added` delivered meanwhile;
  release with a failure -> the device ends `Connected` via the auto path (fails before the change).
- R3: as R2 but the manual connect succeeds -> still the manual source; the auto path opened nothing.
- Existing autoconnect/session tests unchanged and green; `cargo clippy -D warnings`.

## Tests (required)
R1-R3 above in `crates/spectrum-core/tests/autoconnect.rs`, reusing `Bench`/`Gate`/`rig` (no
hardware, no sleeps beyond the existing `wait_for` helper). `npm run check` green.
