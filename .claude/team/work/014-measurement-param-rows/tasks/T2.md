# 014 T2: `NumberField` with no value and an announced unit (`src/ui`, component task)

Goal: the Measurement rows need (a) a `NumberField` that can show "no value" and (b) a unit that screen
readers announce. Spec: DESIGN.md 4.4 ("States: no value", "Unit announced (014)"), 3.6, 9 (a11y).
Components stay presentational (ADR 0015): no state, IPC or bindings imports in `src/ui`.

API change to `src/ui/Field/NumberField.tsx`:
- `value: number | null`. `null` renders an empty input with `placeholder="—"` (secondary text; never the
  label, the `aria-label` stays). With `null`: ArrowUp/ArrowDown do nothing, Enter/blur with no draft
  commit nothing, the range message is not shown, and a typed draft is still validated and committed as
  today (the caller disables the field while there is no source, so this is a safety net).
- Unit announcement: when `unit` is set, the suffix `<span class="ui-field__unit">` gets an id and the
  input's `aria-describedby` includes it (merged with a caller's `aria-describedby`, which today is in
  `...rest`: append, do not overwrite). The suffix stays visible; no extra visually hidden node is
  needed because the visible text is the description. Screen readers then say "Frequency step, kHz".
  This applies to every `NumberField` with a unit (Averaging "traces", Range "dB", Source settings).
- No new tokens, no new props beyond `value` being nullable. FrequencyField already accepts `null`.

Files:
- `src/ui/Field/NumberField.tsx`, `NumberField.test.tsx`, `Field.stories.tsx` (add stories: no value
  disabled with a unit; with unit and a caller description), `src/ui/Field/Field.css` only if the
  placeholder needs the existing secondary text token (use tokens only).
- `DESIGN.md` 4.4: change "Unit announced (014, Proposed ...)" to Approved/implemented wording and add the
  `null`-value description to the "States" line; bump nothing else.

Acceptance:

- `value={null}` shows the `—` placeholder, `ArrowUp` calls nothing, and the input is not marked invalid.

Tests (required): unit tests for both behaviours in `NumberField.test.tsx`; stories render with no axe
