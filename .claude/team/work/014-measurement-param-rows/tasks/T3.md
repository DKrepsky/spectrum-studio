Row rule (generic: never read `driverId`, `kind` of the driver or a device name):
1. `caps = selectedCapabilities(...)`; `measurementParams = caps?.params.filter(p => p.placement === 'measurement')`.
2. Render in this DOM order: `SourceButton`, Center, Span, each measurement param via `ParamField`
   (`layout="inline"`, `id="measurement-<spec.id>"`, flat list, no fieldset), then FFT size and Window
   only when `caps?.dataKind === 'iq'`, then Averaging, the hold row (both kinds), `CaptureControl`.
3. Rows that do not apply are absent from the DOM (not `aria-hidden`, not disabled, no placeholder).
4. No source open (`status.source == null`): device rows (`measurement` params) get `noValue` + disabled
   with the reason text ("Connect a source first", "Connecting…", "Disconnecting…" - the existing
   `processingReason` words) in the tooltip and accessible description; FFT size/Window keep their
   processing values, disabled with the same reason. Averaging and the hold row stay enabled.
5. While `busy === 'applying'` the changed control is `readOnly` (existing mechanism), not disabled.
6. `onChange` of a measurement param calls
   `applySettings({ centerHz: null, spanHz: null, params: { [id]: value } })`: same path, validation and
   error banner as Source settings used.
7. Focus: the panel tracks the last focused control id (`onFocus` on the container). If a layout effect
   finds that control gone and `document.activeElement` is `body`, focus the Averaging input, else the
   source button.
8. Averaging and the hold row still require `status.processing` (unchanged).

Acceptance (maps to #45):
- Trace source connected: rows Center, Span, Frequency step, Reference level, Averaging; hold row and
  capture last; Source settings has no Frequency step or Reference level.
- IQ source: Center, Span, FFT size, Window, Averaging; no device rows.
- Hidden means absent from the DOM; keyboard order equals DOM order; each row announces label, value
  and unit (`kHz`) and the driver help as description.
- Changing Frequency step / Reference level applies as from Source settings (same errors, focus stays).
- Disconnected with a selected trace source seen this run: device rows show `—`, disabled.

Tests (required): see plan "Test plan" for the Vitest list (row sets, absence, DOM order, commits,
focus move, `—` rows, SourcePanel filter) and the e2e steps above. `npm run check` and
`npm run e2e` (simulator specs) pass; SA430 spec only run when hardware is attached.
