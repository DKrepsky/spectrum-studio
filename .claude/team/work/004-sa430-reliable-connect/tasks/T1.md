# T1 — Settle delay, own serial channel and bounded connect retry for the SA430 driver

Parallel: no (single task; all in one crate). Depends on: nothing. Read `plan.md` first (root
cause with evidence). Do not modify the `sa430` crate or `spectrum-core`.

## Goal
After a plug-in the first connect succeeds on the first attempt, and any glitch is recovered by a
bounded retry; a dead/non-SA430 port fails in <= 6 s with the existing actionable message.

## Files
- `crates/spectrum-driver-sa430/Cargo.toml`: add `serialport = "4.8"` (justify in the commit; ADR 0012).
- `crates/spectrum-driver-sa430/src/lib.rs`
- `crates/spectrum-driver-sa430/tests/session.rs`, `tests/hardware.rs`
- `docs/sources.md` (SA430 section), new `docs/adr/0012-sa430-connect-handshake.md` (a draft is
  provided by the staff engineer: review and adjust to what you built).

## Work
1. `SerialBackend::open(port)`: open with `serialport` (926100 baud, 8N1, no flow control, same as
   sa430 channel.rs), sleep `SETTLE` (200 ms), `clear(ClearBuffer::Input)`, wrap in a channel
   struct implementing `Read + Write + Send` whose read timeout is 600 ms until the driver marks
   the handshake done, then 5 s (library default). Return `Sa430::new(Box::new(channel))`.
   Keep the `Sa430Backend` trait shape if possible (add a way for the driver to mark handshake
   done, e.g. the backend returns a small handle, or the wrapper flips itself via a shared flag
   exposed through a trait method with a default no-op for scripted backends).
2. `ConnectPolicy` (attempts 4, backoff [150, 300, 600] ms, deadline 6 s total, handshake
   timeout 600 ms, settle 200 ms) with `Default`; `Sa430Driver::with_backend_and_policy`.
   `Sa430Driver::open` loops: backend open -> `calibration()`; on a retryable error drop the
   device (releases the port), sleep backoff, try again. Retryable: `Io` TimedOut/WouldBlock/
   Interrupted, `Device`, `UnexpectedResponse`, `InvalidData`, frame/CRC errors, and `Serial`
   `PermissionDenied`/`NoDevice` while opening. Not retryable: `InvalidParameter`, serial
   mismatch (never retry a successful identification). Stop when attempts or deadline are
   exhausted; never start an attempt that cannot finish inside the deadline.
3. Final error unchanged in wording: `"{port} did not answer like an SA430 ({last error}). Unplug
   and reconnect the analyzer, then try again."` (open failures keep `open_error` text/hints);
   original error as cause. Log nothing UI-visible; connected state only after calibration read.
4. Docs: `docs/sources.md` SA430 section (device needs ~20 ms after first open; driver settles
   200 ms and retries up to 4 times / 6 s); finalize ADR 0012.

## Acceptance
- Behaviour: scripted first-attempt glitch => `open` succeeds on a later attempt with correct
  serial/label/device_id; persistent failure => `SourceErrorKind::Unavailable`, message as above,
  returns within the policy deadline; the failed attempts leave no open port (drop counter).
- No change to sweep behaviour: after a successful connect reads use the 5 s timeout.
- `cargo clippy -D warnings`, `npm run check` green; no `unwrap` outside tests.

## Required tests
Unit tests in `src/lib.rs` (zero-duration policy, scripted backend that yields a queue of
`Result<Sa430, sa430::Error>` built from `MockChannel` — NoFrameStart = `an_error_response(0x032D)`
queued as the response, timeout = empty MockChannel):
- fails-then-succeeds (NoFrameStart, then full calibration) ; timeout-then-success ;
  NoFrameStart -> timeout -> success (3rd attempt); persistent failure gives up after exactly
  `attempts` tries with the clear message; serial mismatch not retried (1 open call);
  PermissionDenied open retried; each retry opens a fresh device and drops the previous one.
- Backoff/deadline: assert the sum of policy backoffs + worst-case attempt time <= 6 s for the
  default policy (pure arithmetic test on `ConnectPolicy::default()`), and that the loop respects
  a tiny deadline (policy with deadline 0 makes exactly one attempt).
Session test in `tests/session.rs`: connect through `SessionManager` with glitchy-then-good link
=> `Connected`, acquires a frame; persistent failure => `Disconnected`/error surfaced, never
`Connected`. (Note: the existing `ScriptedBackend` hands out its channel once; extend it to a queue.)
Hardware tests (`#[ignore]`, `SPECTRUM_E2E_SA430=1`, bounded waits, no hang): 10 connect/
disconnect cycles all first attempt via `Sa430Driver::open` (expose the attempt count for tests,
e.g. `pub(crate)`-free via a `ConnectPolicy`-returned stat or a test backend wrapper); a
re-enumeration test: `Sa430::reboot()` then wait (<= 5 s) for the port node to vanish and
return, then connect with the default policy => Ok; same with a zero-settle policy => Ok within
<= 3 attempts (proves the retry ladder on real hardware); a connect followed by one real sweep
=> data returned (timeout reverted). Run them yourself on /dev/ttyACM0 (no GUI) and report timings.
