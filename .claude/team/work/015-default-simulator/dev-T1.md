# 015 T1 dev notes: core policy (simulator fallback, idle-simulator replacement, `launching`)

Implements `tasks/T1.md` and ADR 0017. Nothing committed.

## Changed files

- `crates/spectrum-core/src/model/session.rs`: `SessionStatus.launching: bool` (doc; false in `new`).
- `crates/spectrum-core/src/session/mod.rs`:
  - `pub fn set_launching(&self, on)` (publishes via `shared.update`).
  - `pub(crate) fn may_replace(&SessionStatus) -> bool`: `Connected` and `source.simulated`.
  - `connect_if_idle`: returns `Ok(None)` only when a live worker exists and `!may_replace`; otherwise
    shuts the worker down and opens. Doc comments updated.
- `crates/spectrum-core/src/remember.rs`: `auto_connect(..device)` now builds `wanted` and calls the new
  `auto_connect_config(session, store, wanted: SourceConfig)` (remembered lookup, guarded connect,
  `remember`). Device path unchanged.
- `crates/spectrum-core/src/autoconnect.rs`:
  - `Policy::launch`: devices as before; no device -> `launch_simulator()`: first driver with
    `kind == Simulator` and `status == Available` (by kind, not id), `auto_connect_config`. No such
    driver -> debug log. A found device that fails does nothing more.
  - `on_event` Added: `has_active_source()` replaced by `keeps_source()` = `Connected|Acquiring` and
    `!may_replace`. A connect in flight still proceeds to the guard, as before.
  - `AutoConnect::start`: `set_launching(true)` before spawning the coordinator; cleared immediately if
    the spawn fails. `coordinate()` clears it right after `contain("launch", ..)`, so a panic also clears it.
  - Module and method docs updated.
- `crates/spectrum-core/tests/autoconnect.rs`: old "does nothing" tests rewritten (see below); `rig`
  now delegates to `build_rig(devices, hardware, simulator)`, plus `rig_without_simulator`; Bench gained
  `discover_panics`.
- `crates/spectrum-core/tests/session.rs`: new `connect_if_idle` and `launching` tests (added; no other
  test in the file changed in substance).
- `src/bindings/SessionStatus.ts`: regenerated by `npm run bindings` (adds `launching: boolean`).
  `src/bindings/ParamSpec.ts` and `ParamPlacement.ts` also changed by 014 T1 in the same run; not mine.
- `src/test/fixtures.ts`: `status()` builder gets `launching: false`. `tsc` found no other full literal.
- `docs/sources.md` (Auto-connect paragraph: launch fallback, replacement rule, unplug with no
  fallback, `launching`), `docs/architecture.md` (Auto-connect paragraph).
- `src-tauri/`: unchanged; compiles (checked in the workspace gate).
- `crates/spectrum-driver-sa430/`: unchanged. Its tests pass as-is because the test registry has no
  simulator, so the no-device launch stays "nothing connected". I did not add a real-driver replacement
  test there (the core fake covers the rule); candidate for T5 or QA if wanted.

## Tests (rewritten or added, not weakened)

Rewritten: `launch_with_no_device_or_only_the_simulator_does_nothing` (now: idle simulator connected and
remembered, not acquiring, hardware not opened; without a simulator driver nothing connects),
`launch_scan_error_connects_nothing...` (now: scan error falls back to the simulator, failed scan never
opened), `added_while_the_simulator_is_connected_changes_nothing` (now: replaced at launch, replaced
after a manual pick, untouched while acquiring; real device acquiring untouched),
`connect_if_idle_leaves_a_connected_source_alone` (held source is now a real device),
`a_plug_in_while_nothing_is_connected_connects_the_device` (now: plug-in replaces the launch simulator,
waiting for it first so it is deterministic), `without_a_watchable_driver_...` (now: simulator is the
fallback, nothing watched), `shutdown_ends_a_blocked_watch...` and `an_unstoppable_watcher...` (wait
for launch to finish; shutdown does not disconnect).

Added (autoconnect.rs): `launch_with_no_device_connects_the_idle_simulator_and_remembers_it`,
`launch_without_any_simulator_driver_connects_nothing`, `launch_fallback_applies_the_remembered_simulator_settings`,
`launch_with_a_device_does_not_connect_the_simulator`, `unplugging_the_device_gives_no_simulator_fallback`,
`added_replaces_the_idle_simulator_connected_at_launch`, `added_replaces_an_idle_simulator_picked_manually`,
`added_while_the_simulator_is_acquiring_changes_nothing`, `added_while_a_real_device_is_acquiring_changes_nothing`,
`connect_if_idle_replaces_an_idle_simulator_with_a_device`, `a_plug_in_replaces_the_simulator_connected_at_launch`,
`launching_is_true_until_the_launch_rule_has_finished`, `launching_is_cleared_even_when_the_launch_rule_panics`,
`a_manual_pick_during_a_replacement_is_never_replaced` (the guard race), `start_without_a_simulator_or_device_leaves_the_session_idle`.
Strengthened: `launch_failure_shows_connect_failed_and_remembers_nothing` (no simulator source; device is
`last_config`).

Added (session.rs): `connect_if_idle_replaces_an_idle_simulator`, `connect_if_idle_never_replaces_an_acquiring_simulator`,
`connect_if_idle_never_replaces_a_connected_real_source`, `connect_if_idle_connects_when_nothing_is_connected`,
`launching_is_false_by_default_and_follows_set_launching`.

Not covered: the thread-spawn failure path that clears `launching` (needs a fault-injected spawn; the code
is a two-line branch).
