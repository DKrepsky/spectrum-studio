# 015 T2: frontend state - start-up states, selection that is never empty, source button

Goal: R1, R2, R7, R8, R10, R14, B3 of the design. Read `design.md` sections 4-5 and DESIGN.md 5.2.
Needs T1 for the regenerated `SessionStatus.launching` binding and T3 for `simulatorEntry` (`src/state/sourceEntries.ts`).

Files:
- `src/state/session.ts`:
  - `startup: 'loading' | 'ready' | 'unavailable'` in the store. `loading` initially and whenever
    `status === null` or (`status.launching && status.state === 'disconnected'`); `ready` otherwise;
    `unavailable` when `init`'s start-up commands fail (also set `commandError` to
    `Could not reach the backend: <reason>`, `commandErrorFrom: null`). Export a pure
    `startupOf(status, failed)` for tests.
  - `receiveStatus`: also adopt the selection from `status.lastConfig` while `state` is `connecting`, or
    `disconnected` with a `connectFailed` notice, when `busy !== 'connecting'` and the identity differs
    from `useSources.active` (resolve the remembered entry with `sameIdentity`, else
    `{ id: null, title: fallbackTitle(config, drivers), config }`). On a `connectFailed` notice with
    `disconnected`, call `useSources.setFailed(key)` where key is `rowKey(entry)` or `configKey(config)`
    (same keys the menu uses); the existing clearing on connecting/connected/acquiring stays. A
    `deviceLost` stays shown by the existing `lost` logic (Not detected). Disconnect never clears `active`.
  - After a status with a source whose identity is not in `useSources.list`, trigger one
    `useSources.refresh()` (see sources.ts).
- `src/state/sources.ts`: `active` stays `ActiveEntry | null` in the type but is never set to null by the
  app after start-up: `forget` of the active entry while `disconnected` selects the simulator
  (`SIMULATOR_CONFIG`, the remembered unnamed simulator entry if any, title = the simulator driver name)
  instead of `null` (R10); forgetting the connected source still keeps its name until another pick
  (unchanged). `refresh()` re-adopts the active entry by identity when `active.id == null` and a list
  entry matches (the backend remembers an auto-connect just after publishing Connected). Keep
  `init()` never connecting.
- `src/components/source/status.tsx`: no change to mappings except: a selected, not connected source is
  `idle` (already); add `startup`-aware helpers only if needed by `SourceButton`.
- `src/components/source/SourceButton.tsx`: by `startup`: `loading` -> text "Loading…" in the secondary
  text colour, no dot, no `attention` outline, `aria-label="Source: Loading…"`, still a button that does
  not open the menu (disabled-looking but focusable: use `aria-disabled`, not `disabled`);
  `unavailable` -> "Status unavailable", same style, accessible name `Source: Status unavailable`;
  `ready` -> name + dot + state exactly as today. Keep the old "Choose a source" label only as the
  unreachable fallback for `ready && active === null`, with a comment (no simulator driver registered).
  Update `source.css` only through existing tokens; `source.css.test.ts` must stay green. Ctrl+K while
  not `ready` does nothing.
- `src/test/fixtures.ts`, `src/test/mockApi.ts`: status builder takes `launching`; mock `getStatus`
  failure path for the unavailable test.
- Tests: `session.test.ts`, `sources.test.ts`, `SourceButton.test.tsx`, `status.test.ts`, `App.test.tsx`
  (updates where it asserted "Choose a source").

Acceptance:
- Before the first status: button "Loading…". Status with `launching` and no connect begun: still
  "Loading…". Then the device or simulator name with Connecting… / Connected.
- Backend failure on start-up: "Status unavailable" and one banner with the reason.
- Launch with a failed device: name + red cross "Failed", Reconnect banner (existing `NoticeBanner`),
  no simulator.
- Disconnect: name stays, idle dot, accessible name `Source: <name>, Disconnected`.
- Forget of a selected, not connected source: simulator selected, not connected.
- Auto-connect never moves focus or closes the open menu (no focus calls in the new code paths).

Tests (required): listed per file above; they assert visible text and accessible names, not store
internals. `npm run check` passes.

Dependencies: T1, T3. Parallel: no (after both). Overlaps 014 T3 on `session.ts`: merge 014 T3 first.
