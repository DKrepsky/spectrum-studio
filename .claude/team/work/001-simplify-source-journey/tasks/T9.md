# T9 Core contract: new types, OpenedSource identity fields, normalize hook, resolved config, bindings

Read first: `../plan-rework.md` sections 3.1 and 6, `docs/adr/0010-stable-device-identity.md`, `docs/sources.md`.
Depends on: nothing. **First task; small and mechanical. Parallel: none** (T10, T11, T13 start when it lands).

## Goal
Add the shared contract so the driver, store, command and frontend tasks can proceed in parallel. No behaviour change except
the worker storing the resolved config. Do not implement SA430 or store logic here.

## Files (exact)
- `crates/spectrum-core/src/model/source.rs`: add `DeviceDescriptor.location: Option<String>` (serde default; doc: where the device is
  attached now, e.g. a port; also used as a connection hint); new exported structs `SourceUpdate { name: String, device_id: Option<String>,
  connection: ParamMap }` and `SourceTestResult { ok: bool, message: String, device_id: Option<String>, label: Option<String>, in_use: bool }`
  (`serde(rename_all = "camelCase")`, ts-rs behind the `bindings` feature like neighbours). Re-export from `lib.rs`/`model/mod.rs` as needed.
- `crates/spectrum-core/src/sources/mod.rs`: `OpenedSource` gains `device_id: Option<String>` and `connection: ParamMap`
  (doc comments from plan 3.1); `SourceDriver::normalize_device_id(&self, Option<&str>, &str) -> Option<String>` default `None`.
- `crates/spectrum-core/src/sources/registry.rs`: `DriverRegistry::normalize_device_id(driver_id, device_id, label)` passthrough (unknown driver -> None).
- Mechanical literal updates: `sources/simulator/mod.rs`, `sources/files.rs` (both file drivers), `sources/planned.rs`, test drivers in
  `crates/spectrum-core/tests/session.rs`, and the one `OpenedSource {` and `DeviceDescriptor {` literal in `crates/spectrum-driver-sa430/src/lib.rs`
  (`device_id: None, connection: ParamMap::new()`, `location: None`; T10 fills them in).
- `crates/spectrum-core/src/session/worker.rs` (around line 79 where `ActiveSource` is built): `config.device_id = opened.device_id.or(config.device_id)`
  and `config.connection` = given connection with `opened.connection` entries overlaid (opened wins). Keep `last_config` as given.
- `src/bindings/**`: `npm run bindings`, commit the output (`DeviceDescriptor`, `SourceUpdate`, `SourceTestResult` new/changed).

## Acceptance
- `npm run check` green; bindings regenerated and contain exactly the three type changes.
- No behaviour change for existing drivers except `ActiveSource.config` carrying the driver-reported identity.

## Tests (required)
- `crates/spectrum-core/tests/session.rs`: scripted driver whose `open` returns `device_id: Some("X1")` and `connection {"port":"/dev/x"}`: connecting with
  `device_id: None, connection {}` yields `status.source.config.device_id == Some("X1")` and `connection["port"] == "/dev/x"`; a driver returning `None`/empty leaves the
  given config unchanged; `status.last_config` is still the given config.
- Registry test: `normalize_device_id` returns the driver's answer and `None` for an unknown driver.
