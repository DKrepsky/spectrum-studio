# T8 - Automated visual guard (overflow assertion + key-state screenshots)

Added by Amendment 1 (item 4). Supplements, never replaces, QA looking at screenshots.

## Goal
An e2e spec that fails when text in the source button or a menu row is clipped without deliberate
truncation, and saves screenshots of key states for QA to inspect.

## Files
- new `e2e/specs/visual.e2e.ts`; small helper in `e2e/specs/helpers.ts` (`assertNoOverflow`,
  `shot(name)` writing to `e2e/logs/visual/`). Reuse `e2e/tools/screenshot.ts` window setup.
- test ids: use the existing `source-button` / `source-menu` / row ids; add a `data-truncated`
  convention only if the design specifies deliberate truncation (then rows with the attribute are
  exempt from the check but must expose the full name via `title`).

## Behaviour
- Seed the config dir (as `migration.e2e.ts` does with `e2e/fixtures/`) with remembered sources
  whose names include a 60-char name and "SA430 08FF41E50F8B3A34"; run with the simulator and
  the SA430 fixture the other specs use.
- For window widths 1280 and the narrowest supported width (design): open the menu and, for the
  source button and every `[role=menuitem]`/row element and its text children, assert
  `scrollWidth <= clientWidth` (+1 px tolerance) unless the element is marked as deliberately
  truncated, in which case assert `title`/accessible name equals the full text. Also assert the
  menu's bounding rect lies inside the window.
- Screenshot: empty (no sources), typical, long names, narrow window, and the Add source dialog
  states once T-dialog exists (skip those until then).

## Acceptance
- `npm run e2e -- --spec e2e/specs/visual.e2e.ts` passes with the fixed UI and fails when the
  long-name CSS is reverted (check by hand once; note it in the handoff).
- `npm run check` green (e2e `tsc` included).

## Dependencies
After the UI rework tasks (it asserts their layout); touches only e2e files, so it can run in
parallel with backend tasks.
