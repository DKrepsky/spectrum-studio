## Work
1. `src/ipc/commands.ts`: add `addSource(name, config)`, `updateSource(id, update)`, `testSource(driverId, connection)`; remove `renameSource`. `src/test/mockApi.ts` + `fixtures.ts`: implement them with the same rules the
   backend has (name uniqueness case-insensitive excluding self, duplicate identity message, lock rule, rebind duplicates, test results keyed by port: `/dev/ttyACM0` ok with serial, `/dev/ttyACM2` another serial,
   `/dev/ttyUSB9` fails, others time out - the same table as the prototype) so component tests can drive every dialog state. Include `location` in mock `DeviceDescriptor`s.
2. `src/state/sourceConfig.ts`: `sameIdentity` = driver + deviceId when both set, else driver + connection (mirror of Rust). Update users (`session.ts receiveStatus`, `connectTo`).
3. `src/state/sources.ts`: remove `rename`; add `addSource(name, config) -> SavedSource`, `updateSource(id, update) -> SavedSource` (both refresh the list, keep the toolbar title in sync with the edited active entry),
   `testSource(driverId, connection) -> SourceTestResult` (no state change). They throw/return the backend message for display; they never mutate state on failure. After a connect, if `active.id` is not in the refreshed list, adopt `list.activeId`.
4. `src/state/sourceEntries.ts`: `YourRow.port`, `DetectedRow.port` (scan `location` else `connection.port` hint), `isActiveBusy(state, busy, activeId, entryId)` for the lock, `dialogDrivers(drivers)` = `otherDrivers` (rename kept as alias),
   `defaultName(device)`; `TRANSPORT_LABEL` unchanged. Presence/dedupe unchanged: tests below.
5. `src/components/source/SourceDialog.tsx`: stub exporting `DialogTarget`, `SourceDialogProps`, and a placeholder `SourceDialog` that renders `null` (contract in plan section 5). No other component file is touched.
