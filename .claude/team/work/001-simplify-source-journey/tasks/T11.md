# T11 Store: identity match, v3 migration with backup, add/update, merge on connect

Read first: `../plan-rework.md` sections 3.2, 4, `../investigation-duplicates.md`, ADR 0010 and the amended 0006, `crates/spectrum-core/src/store.rs`, `remember.rs`.
Depends on: T9 (types). Parallel with T10 and T13. Owns `store.rs`, `remember.rs`, `tests/remember.rs`, `e2e/fixtures/seed/migration/**`.

## Goal
Make the store identity-correct, migrate the user's duplicated store losslessly, and provide the create/edit operations behind `add_source`/`update_source`.

## Work
1. `same_identity(a, b)`: both have `device_id` -> `driver_id` + `device_id` (connection ignored); neither has -> `driver_id` + `connection`; one has and one hasn't -> not the same.
2. `SOURCES_SCHEMA_VERSION = 3`; `ConfigStore::open_with(dir, normalize)` (plan 3.1) and `open(dir)` = `open_with(dir, &|_,_,_| None)`. Migration exactly as plan section 4 (normalize, merge rules, survivor rule,
   `lastSourceId` repoint, store warning on a dropped name, backup `sources.pre-v3-<epoch ms>.json` via copy, atomic rewrite, failure handling, `version > 3` untouched). Put the merge in one function
   `merge_records(group) -> SavedSource` reused by connect-time merging.
3. `remember_connected`: uses the resolved `active.config` (already carries `device_id`/port). If the target (by `id`, else by identity) resolves to a `device_id` already owned by *another* record, merge the two
   (survivor rule) and return the survivor; `last_source_id` handling in `remember.rs` already uses the returned id. Failed connects still remember nothing.
4. New `ConfigStore::add_source(name, config, driver: &DriverInfo, driver_available)` and `update_source(id, &SourceUpdate, driver info, locked: bool)` per plan 3.2 (validation order and messages exactly as listed there;
   keep the validation as a pure function `validate_name(list, name, except_id)` for unit tests). Name uniqueness compares the trimmed, case-insensitive effective name (`name` else `label`) of the other records.
   `locked` is computed by the caller (`remember.rs` helper `is_in_use(status, record)`: session state in connecting/connected/acquiring/disconnecting and resolved identity matches). `MAX_RENAME_LENGTH` becomes `MAX_NAME_INPUT = 60`.
5. Remove `rename_source` from `ConfigStore` and its tests (replaced by `update_source` tests). `restore_source` additionally rejects a record whose identity is already remembered.
6. `remember.rs`: add `add_source(session, store, name, config)`, `update_source(session, store, id, update)` orchestration (looks up driver info via `session.drivers()`, computes the lock from `session.status()`), returning `SavedSource`.
7. e2e seed: leave `e2e/fixtures/seed/migration/` untouched; add the exact two-entry store from the investigation as `e2e/fixtures/seed/migration-dup/sources.json` (used by T16).

## Acceptance
`cargo test --workspace` green, `npm run check` green, clippy clean. No UI change.

## Tests (required) - the nine cases listed in plan section 4 (a-i), plus
add: each error string, case-insensitive name collision, collision excluded for self on update, internal/file driver rejected, no-id discovery driver with empty port rejected, duplicate identity message names the other record,
200 cap eviction; update: rebind to a free serial ok, to an owned serial rejected, lock rejects a port change but allows a name change, simulator/file rename-only, unknown id, `last_used_ms` untouched, settings kept;
restore: duplicate identity rejected; `same_identity` table.
