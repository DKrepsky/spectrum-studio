# T12 `test_source`, Tauri commands and wiring

Read first: `../plan-rework.md` sections 3.2 and 6, ADR 0010, `crates/spectrum-core/src/session/mod.rs`, `src-tauri/src/{commands,lib}.rs`.
Depends on: T9, T10, T11. Parallel with T13, T14, T15. Owns `session/mod.rs`, `tests/probe.rs`, `src-tauri/src/**`.

## Work
1. `SessionManager::test_source(&self, driver_id, connection: ParamMap) -> Result<SourceTestResult, SessionError>`: behaviour exactly as the `test_source` row in plan 3.2 (validate driver `Available`
   and `resolve_params`; busy/in-use/timeout results; a `Mutex<()>` or `AtomicBool` single-flight separate from `worker` and `scan`; open on a short-lived thread, 8 s timeout via `recv_timeout`, then drop the
   source on that thread; success -> `ok`, `device_id = opened.device_id`, `label = opened.label`, message `Connection OK. <driver name> found.`; failure -> backend message verbatim via `SourceError::message`, plus `error_chain` in a `tracing::debug`).
   It must not call `shared.update`, take the `worker` lock, or modify the store.
2. Commands in `src-tauri/src/commands.rs`: `add_source`, `update_source`, `test_source` (blocking pool like the others; mapping core errors to `CommandError` with the message verbatim); remove `rename_source`.
   Register in `lib.rs` `generate_handler!`. `lib.rs`: open the store with `ConfigStore::open_with(dir, &|driver, id, label| registry.normalize_device_id(driver, id, label))` where the registry is built first and shared
   (build `driver_registry()` once, give the store a reference to the hook before moving the registry into the session). Report `store.warnings()` as today.
3. `npm run bindings` (expected empty diff), commit anything that changes.
4. `docs/sources.md` contract paragraph is written in T16; add Rust doc comments for the new trait items now.

## Acceptance
`npm run check` green; `cargo test --workspace` green.

## Tests (required)
`crates/spectrum-core/tests/probe.rs` (scripted drivers): ok result carries device id/label; driver error -> `ok:false` with the exact message; unknown/planned driver -> `Err`; in-use when connected with the same port value
(and the driver `open` is NOT called a second time); busy while `Connecting` (use a driver whose `open` blocks on a channel); two concurrent tests -> second is Busy; timeout path with a driver that sleeps past a test-only shortened timeout
(make the timeout a field with default 8 s, settable in tests); the session status `revision` is unchanged by a test and an acquiring session of another driver keeps producing frames during the test.
`src-tauri` has no test harness for commands: keep commands one-liners over tested core functions; add a small compile-level unit test if the crate already has tests, otherwise rely on T16 e2e.
