## A. Focus must stay in the menu (finding 1)
Files: `src/components/source/SourceMenu.tsx`, `src/components/source/SourceMenu.test.tsx`.
Problem: Forget moves focus to Undo (inside the toast). Clicking Undo, or the 5 s toast expiring,
removes the focused button; focus falls to `<body>` and the Escape/arrow handler (on the `role=menu` div) never fires.
Fix: whenever the menu is showing the list and `document.activeElement` is not inside `popover`
after `forgotten` changes (Undo clicked, expired, or a restore), move focus: to the restored row
(`source-entry-<id>` of the undone entry) after Undo, else to the nearest remaining enabled item, else the
`menu` div (it has tabIndex -1). Implement in the existing `[forgotten]` effect (extend it; use
`useLayoutEffect` or rAF so the DOM has updated). Also apply when a rename finishes and the row vanished.
Acceptance: after Forget -> Undo, focus is on the restored row and Escape closes the menu and returns focus
to `source-button`. After Forget and 5 s expiry (fake timers) focus is still inside the menu and Escape closes it.
Tests (assert behaviour via `document.activeElement` and menu presence): both cases above, plus Forget the only
row then Undo.
Also remove the `void rows.splice(...)` oddity (`void` is pointless; use a plain statement).
