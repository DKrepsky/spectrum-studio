# T3 `src/ui`: controls (Button, IconButton, Spinner, InlineMessage, Field family)

Goal: build the control components with tests, unwired (no feature file changes).
Dependencies: T1. Parallel: yes with T2, T4, T5 (disjoint folders).

Files (all new): `src/ui/Button/`, `IconButton/`, `Spinner/`, `InlineMessage/`, `Field/` (Field, TextField, NumberField, FrequencyField, Select, Checkbox), each with `.tsx`, `.css`, `.test.tsx`, `index.ts`. Props per plan.md section 4; DESIGN.md 4.1, 4.2, 4.4, 4.5, 4.6, 4.10, 9.9, 9.10.
Rules:
- CSS: only tokens, class prefix `ui-`; sizes `--control-height`, `--control-height-small`, `--field-height-compact`, `--target-min`; opacity `--opacity-unavailable` (F9); field boundary `--color-border-input` (F15); small/icon min 24px (F2); checkbox label min-height 24px (F14); one inline error size (F8); focus ring tokens, offset `--focus-ring-offset`.
- `NumberField` and `FrequencyField` port the logic of `src/components/NumberInput.tsx` / `FrequencyInput.tsx` unchanged (commit on Enter/blur, Escape reverts, invalid not sent, step on arrows); move their tests' assertions into the new test files. The old files stay until T6/T7 delete them (do not edit them here).
- `Button`: `unavailable` = `aria-disabled="true"`, click ignored, focus kept; `busy` shows `Spinner`, keeps label width.
- All components forward native attributes and `data-testid`; `IconButton` requires `label`. Must pass the boundary test and ESLint override.
Acceptance: `npm run check`; tests cover variants, sizes (class assertions), states (unavailable ignores click and stays focusable), keyboard (Enter/Space, field commit rules), ARIA (names, `aria-invalid`, `aria-describedby` wiring through `Field`). No consumer changes.
